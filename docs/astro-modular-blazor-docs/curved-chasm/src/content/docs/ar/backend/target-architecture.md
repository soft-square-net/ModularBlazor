السيناريوهان A وB إعدادان للتصميم نفسه: **صورة واحدة تنشر كمجموعات، وكل مجموعة تفعل مجموعة من الوحدات ودورا.**

```text
Blazor WASM client                                    CDN: _framework and static files
   │ (tenant from host name or claim)
   ▼
Edge load balancer + YARP gateway                     TLS, JWT, rate limit, tenant resolution
   │  /sales/*  ─────────────────────┐
   │  everything else ──┐            │
   ▼                    ▼            ▼
┌──────────────────────────────────────────────────────────────────────┐
│ one image · EnabledModules + Role per pool                           │
│  Core pool                 Sales pool             Worker pool        │
│  Identity · Workflow       Sales                  consumers + jobs   │
│  Inventory · ×2            ×4 · autoscaled        ×2 · scale on lag  │
└──────────────────────────────────────────────────────────────────────┘
        │                      │                         │
   Message broker          Redis                    Tenant data
   outbox → topics → DLQ   cache, locks, keys       tenant store + tenant databases
                                                    · object store
Observability: OpenTelemetry traces, metrics and logs, tagged with tenant and correlation ids
```

## مجموعات من صورة واحدة

يقرأ كل نشر للصورة ثلاثة إعدادات (مطبقة في النموذج الأولي `src/WebApi/WebApi`):

| الإعداد | القيم | الأثر |
| --- | --- | --- |
| `Modules:Pool` | `core` أو `sales` أو `worker` أو غيرها | اسم المجموعة، ويظهر في الحالة والسجلات ورسائل البث |
| `Modules:Enabled` | معرفات وحدات، مثل `identity` و`workflow` و`inventory`؛ والفارغة تعني الكل | الوحدات التي تحملها هذه المجموعة وتربط مساراتها وتسجل خدماتها |
| `Modules:Role` | `Api` أو `Worker` | `Api` يربط نقاط نهاية HTTP؛ و`Worker` يحمل الوحدات لمستهلكي رسائلها ومهامها المجدولة، دون مسارات |

```text
Scenario A           all    = Enabled: (all)              Role: Api      ×N
Extract one module   core   = Enabled: all but sales      Role: Api      ×2
                     sales  = Enabled: sales              Role: Api      ×4
                     worker = Enabled: (all)              Role: Worker   ×2
```

لنقل وحدة إلى مجموعتها الخاصة: أضف نشرا بقيمة `Modules:Enabled` الخاصة بها، وأضف عنقود YARP لمسارها، وبدل تسجيل
عقدها في المجموعات الأخرى من التنفيذ الداخلي إلى عميل gRPC. لا تتغير شيفرة الوحدة. ومكان هذا التبديل هو سجل
وحدات المضيف (`HostModules`).

تقرأ كل المجموعات **فهرس الوحدات نفسه**. أي تغيير في دورة الحياة عبر أي نسخة يكتب في الفهرس ويبث على الوسيط، وتطبقه
كل نسخة بحسب قائمة `Enabled` و`Role` الخاصين بها؛ انظر [وحدات أثناء التشغيل](/ar/backend/runtime-modules/).

يشغل [مختبر البنية الهجينة](/ar/backend/hybrid-lab/) هذا التصميم محليا عبر .NET Aspire: بوابة YARP، ومجموعات core
وsales والعمال، وRabbitMQ وRedis وPostgreSQL.

## مسار الطلب

1. ينزل العميل `_framework` والملفات الثابتة من CDN؛ ولا تصل إلى البوابة إلا استدعاءات الواجهة البرمجية.
2. تتحقق البوابة من JWT، وتطبق حدود المعدل، وتحدد المستأجر، وتمرر الطلب إلى المجموعة المالكة للمسار. ولا تتلقى
   مجموعة العمال أي حركة HTTP.
3. داخل المجموعة، استدعاء وحدة موجودة في المجموعة نفسها استدعاء داخلي عبر عقدها؛ واستدعاء وحدة في مجموعة أخرى
   استدعاء gRPC مباشر، لا يمر أبدا عبر البوابة.
4. تكتب تغييرات الحالة في قاعدة بيانات الوحدة وفي صندوق الصادر الخاص بها ضمن معاملة واحدة؛ وينشر المرحل إلى
   الوسيط؛ ويعالج الرسالة المستهلكون في أي مجموعة تستضيف الوحدة المشتركة.

تجد كيفية فحص الرموز وعضوية المستأجر والصلاحيات على هذا المسار في
[مذكرة تصميم المصادقة والتفويض](/ar/backend/auth-design/) (قرار تصميم، غير منفذ بعد).

## البنية التحتية المشتركة

| المكون | يحمل |
| --- | --- |
| **Redis** | مفاتيح Data Protection، و`HybridCache`، والأقفال الموزعة للمهام المجدولة، وSignalR backplane، وعدادات تحديد المعدل، وذاكرة إعدادات المستأجرين |
| **وسيط الرسائل** | مواضيع أو مبادلات لكل نطاق، ومستهلكون متنافسون، وطوابير رسائل ميتة. ناقل منطقي واحد: الوسطاء المنفصلون لكل خدمة يقسمون تدفق الأحداث |
| **بيانات المستأجرين** | مخزن المستأجرين (تملكه وحدة واحدة) وقواعد بيانات المستأجرين؛ انظر [تعدد المستأجرين](/ar/backend/multitenancy/) |
| **تخزين الكائنات** | الملفات المرفوعة والوسائط؛ لا تحتفظ الحاويات بملفات على قرصها المحلي |

تشغل الترحيلات مرة واحدة لكل إصدار كمهمة قبل النشر، ولا تشغل أبدا عند بدء كل نسخة.

## المراقبة

- **التتبعات** تعبر البوابة والمجموعات والوسيط: ينتقل سياق تتبع W3C في ترويسات HTTP وترويسات الرسائل، فيظهر في
  تتبع واحد الطلب والنشر من صندوق الصادر والمستهلك.
- **كل نطاق تتبع وكل سطر سجل** يحمل `tenant.id` ومعرف الربط.
- **مقاييس** لكل مجموعة: معدل الطلبات وزمنها، وتأخر المستهلكين لكل طابور (تتوسع مجموعة العمال بحسبه)، وتراكم
  صندوق الصادر، وعدد الرسائل الميتة.
- **محليا**، يشغل .NET Aspire البنية كلها (المجموعات والوسيط وRedis وقواعد البيانات) مع لوحته.

## أخطاء يتجنبها هذا التصميم

| خطأ شائع في المخططات | هنا |
| --- | --- |
| رسم CDN خلف موازن الحمل | يحمل العميل الملفات الثابتة من CDN مباشرة |
| موازن حمل أمام البوابة *و*بوابة توازن مرة أخرى | طبقة طرفية واحدة؛ ويوازن YARP بين نسخ المجموعة، بوجهة لكل نسخة (العنوان الافتراضي الواحد ثبت كل الحركة على نسخة واحدة في المختبر) |
| خدمات تستدعي بعضها عبر البوابة العامة | استدعاءات داخلية مباشرة فقط |
| وسيطان لمجموعتين من الخدمات | ناقل منطقي واحد |
| طابور "يكتب" إلى التخزين | المستهلكون يقرؤون الطابور ويكتبون إلى التخزين |
| كتابات تذهب إلى فهرس البحث | تذهب الكتابات إلى قاعدة بيانات الوحدة؛ والفهرس إسقاط تغذيه الأحداث |
